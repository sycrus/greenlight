# Spec: Google Slides Pre-Production Deck

## Overview

Stage 4 generates a Google Slides pre-production deck from the parsed brief, creative territories, and Visual DNA. Two variants are produced: an ECD-facing internal version (with risk flags and rationale) and a client-facing external version (clean presentation).

## Slide structure

### ECD version (internal — all slides)

| # | Slide name | Content |
|---|---|---|
| 1 | Title | Campaign brand, run ID, date generated |
| 2 | Brief Summary | Parsed objective, audience, key message, gaps |
| 3 | Territory 1 Cover | Name, creative proposition, tone descriptor |
| 4 | Territory 1 Visual | Mood description, palette swatches, cinematography style |
| 5 | Territory 1 Details | Scene arc, scene count, flow prompt style, risk flag |
| 6 | Territory 2 Cover | Name, creative proposition, tone descriptor |
| 7 | Territory 2 Visual | Mood description, palette swatches, cinematography style |
| 8 | Territory 2 Details | Scene arc, scene count, flow prompt style, risk flag |
| 9 | Territory 3 Cover | Name, creative proposition, tone descriptor |
| 10 | Territory 3 Visual | Mood description, palette swatches, cinematography style |
| 11 | Territory 3 Details | Scene arc, scene count, flow prompt style, risk flag |
| 12 | Visual DNA Overview | All 3 palettes side by side, cinematography comparison, ingredient counts |
| 13 | Brand Alignment | Brand rules applied per territory, risk flags, divergence notes |
| 14 | Approval | Territory radio list, instructions for ECD |
| 15 | Next Steps | What happens after approval |

### Client version (external — internal slides removed)

Same as ECD version but omits slides 13 (Brand Alignment) and hides risk flags on territory detail slides. Approval slide instructions are reworded for client audience.

## Gemini prompt

The deck copy prompt (`lib/prompts/deck-copy.ts`) takes as input:
- Parsed brief (brand, objective, audience, key message, tone_descriptors)
- 3 territories (all fields)
- 3 Visual DNA objects (palette, cinematography, ingredients, brand_rules_as_prompts)

Returns structured JSON with all slide text. One Gemini call generates copy for all slides — not one per slide.

## Slides API operations

### Create presentation
```
POST https://slides.googleapis.com/v1/presentations
Body: { title: "Greenlight — {brand} Pre-Production Deck" }
```

### Populate slides (batchUpdate)
Each slide is created via `createSlide` with a layout + `insertText` for content:
- TITLE_AND_BODY layout for territory slides
- TITLE layout for cover slides
- BLANK layout for visual overview (custom text box placement)

### Replace text placeholders
Use `replaceAllText` requests to fill in copy generated by Gemini:
- `{{BRAND}}` → brand name
- `{{TERRITORY_1_NAME}}` → territory 1 name
- `{{T1_PROPOSITION}}` → territory 1 proposition
- ...etc for all slide content

## Sharing

### ECD deck
- `drive.permissions.create()` with `role: "commenter"`, `type: "user"`, `emailAddress: ECD_EMAIL`
- Returns `https://docs.google.com/presentation/d/{id}/edit`

### Client deck
- Duplicate ECD deck via `drive.files.copy()`
- Remove internal slides (Brand Alignment)
- Remove risk flag text from territory detail slides
- `drive.permissions.create()` with `role: "reader"`, `type: "user"`, `emailAddress: CLIENT_EMAIL`
- Returns `https://docs.google.com/presentation/d/{id}/view`

## Error scenarios

1. **Slides API returns 429** → retry after delay, return error with retry-after to UI
2. **Drive share fails (invalid email)** → return 400 with "Invalid email: {email}"
3. **Gemini deck copy generation fails** → retry once, return partial deck if retry also fails
4. **Missing territory data** → return 400 with "Run {runId} has no territories — run Stage 2 first"

## Validation

- Slide count matches expected (15 ECD, 14 client)
- All territory names appear in deck
- Palette swatches match Visual DNA hex values
- Approval slide lists all 3 territories
- ECD deck URL returns 200
- Client deck URL returns 200
